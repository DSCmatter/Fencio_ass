Generated by Phase 3. All counts and examples below come from the real runs of
`training/download_datasets.py` and `training/prepare_dataset.py` on 2026-11-26.

in `data/processed/`. No model was loaded, trained or served locally.

## 3. Processed structure

`training/prepare_dataset.py` produces three chat-format tasks. Every record has
`id`, `task`, `category`, `source`, `seed_source`, and `messages` with exactly
`system`, `user`, `assistant` roles.

| Task | `system` | `user` (JSON string containing) | `assistant` |
|---|---|---|---|
| `attack_generation` | offensive-model role and output rules | `category`, `target_capabilities`, `prior_attempts`, `tactic` | one plain-text next attack payload |
| `response_analysis` | defensive-analyst role and strict JSON rule | `attack`, `target_response`, `tool_trace` | strict JSON string `{"vulnerable": bool, "category": str, "evidence": str, "confidence": float}` |
| `strategy_planning` | planner role and strict JSON rule | `state_summary` | strict JSON string `{"next_category": str, "rationale": str, "tactic": str}` |

Categories: `prompt_injection`, `jailbreak`, `indirect_injection`, `tool_abuse`,
`system_prompt_extraction`, `data_exfiltration`, `memory_poisoning` (plus a
`benign` label in response-analysis records). Each task is built from
hand-written records and programmatic template expansion: 7 hand-written
records per task, 6 tactics per category, 6 target capabilities, 5 sandbox
goals, 2 prior-attempt variants, plus sampled labelled public seeds. All
generated targets use demo canaries (`CANARY-SYSPROMPT-DEMO`,
`CANARY-SECRET-DEMO`) and never request real-world harmful actions.

Every processed record carries `"source": "synthetic"` (all records are
constructed by the preparation script) and a `seed_source` field recording
provenance: `handwritten` or the originating public dataset id. De-duplication
uses the exact triple `(task, whitespace-normalised user, whitespace-normalised
assistant)`. The split is stratified by `(task, category)` with seed
`20261126`; validation and test are disjoint from train by construction and the
script asserts this before writing. `data/processed/split_stats.json` records
the checks.

## 6. Limitations

- Targets are templated and repeat a small set of canary strings; a model may
  overfit to these phrasings. Real target responses and real tool traces were
  not used as training targets.
- Response-analysis verdicts and confidence values are authored by templates,
  not human-annotated or calibrated on a held-out labelled set.
- De-duplication is exact after whitespace normalisation; near-duplicate
  paraphrases remain possible.
- Category balance is uneven: `prompt_injection` is over-represented because
  three public sources are injection-focused.
- English only; no multi-modal or multilingual coverage.
- The deepset licence metadata conflict is disclosed above and cannot be fully
  resolved from the repo alone (no LICENSE file). Both candidate licences are
  permissive, but downstream users should preserve attribution.
- The 4 GB local GPU was never used for model work; this phase ran lightweight
  Python only. Fine-tuning and inference belong on Kaggle/Colab as described in
  `PLAN.md`.
- The test split is held out here but has not yet been used; Phase 4 must use it
  only for base-vs-tuned evaluation.
